FUNCIONES SQL

Todas las operaciones sobre el árbol deben usar una misma conexión y transacción.

1. ttree_build(tabla regclass, columna text) -> bigint
   Lee claves INTEGER de una tabla PostgreSQL con SPI y construye el árbol.
   Devuelve la cantidad de claves. Error si hay NULL, duplicados o tipo incorrecto.
   Sustituye el árbol anterior. No crea un índice nativo del catálogo.

2. ttree_contains(clave integer) -> boolean
   Busca en el árbol. true si existe; false si no existe.

3. ttree_insert(clave integer) -> boolean
   Inserta solo en el árbol. true si insertó; false si era duplicada.
   Para mantener tabla e índice coherentes, ejecutar INSERT en la tabla y esta
   función dentro de la misma transacción. No es un trigger automático.

4. ttree_range(minimo integer, maximo integer) -> SETOF integer
   Devuelve las claves del intervalo inclusivo. Intervalo invertido: vacío.
   El recorrido interno es ordenado; usar ORDER BY al requerir orden contractual SQL.

5. ttree_validate() -> boolean
   Verifica orden, límites, alturas, balance, ocupación y contadores.
   Devuelve true o produce error con la primera propiedad incumplida.

6. ttree_stats() -> text
   Cantidad de claves, nodos, altura, capacidad, mínimo interno y bytes del núcleo.
   Los bytes no incluyen overhead del asignador ni la memoria temporal de SPI.

7. ttree_reset() -> void
   Libera el árbol de la transacción actual.

COMMIT/ROLLBACK finalizan el estado del índice. Después de ROLLBACK TO SAVEPOINT,
reconstruirlo. Un error capturado mediante EXCEPTION de PL/pgSQL también puede
abortar una subtransacción e invalidarlo. El índice no se comparte entre conexiones.
